C4 Level 2 — Containers

Read this first

There is one deployed process. It serves the Blazor WebAssembly bundle as static files and hosts the API. No gateway, no separate front-end host, no background worker service.

That single fact explains several constraints elsewhere: why route ordering between MapApiEndpoints() and MapFallbackToFile() matters, why static files must be served before UseAuthorization, and why the analysis runs on a background Task inside the web process rather than in a queue worker.

Two external services participate in requests: GitHub (OAuth, REST, and git-over-HTTPS) and Azure Table Storage. Key Vault and the telemetry exporters are infrastructure, drawn dashed because they do not sit on a request path.

C4 Level 3 — Components inside the API

Slices are peers that never touch

Each feature owns its endpoints, commands/queries and handlers in one folder under Features/{Name}/. Slices must not reference each other — GlobalUsings.cs deliberately omits Features.*, so cross-slice coupling needs an explicit using and shows up in review. Only Extensions/, the composition root, has one.

What two slices both need moves down into Auth/ or Shared, never sideways. That is why RepositoryOwnership lives in Auth/: a copied authorization check fails quietly, and the symptom is a route serving another user's data rather than a broken build.

The yellow band is the cross-cutting layer slices are allowed to depend on; the green band is storage and domain services, all scoped except the progress service, which must be a singleton to track jobs across background tasks.

Pipeline 1 — Sign-in

Why GitHub only

Microsoft/Entra sign-in was removed deliberately. The app's entire purpose is reading GitHub repositories, and a Microsoft-authenticated principal carries no GitHub credential. The old handler stored the Microsoft token in User.AccessToken — a field documented as the GitHub token — so every GitHub call sent it to api.github.com and got a 401. A second sign-in button that cannot reach the app's only data source is worse than no second button.

Two details that look like bugs and are not. SameSite=Lax, not Strict: after returning from GitHub the browser withholds a freshly-set Strict cookie on the landing redirect, producing an infinite “pick an account” loop. And storage failure does not fail the sign-in — a warning is logged and a temporary UserId claim keeps the session usable.

Pipeline 2 — Analysis

Queue, don't hold the request

A full history replay takes minutes, so the endpoint verifies ownership, queues the work on a background task with a fresh service scope, and returns 202. The request scope dies with the response — resolving IMediator from it would hand the job disposed dependencies.

Progress reaches the browser one way: the hub pushes frames, and the poll fallback exists only for when the hub is unreachable, where it synthesises the same frames rather than handling completion itself. There used to be three completion paths and they had drifted.

Two performance properties are load-bearing. Line counts are memoised on git object ids, so an unchanged directory between two commits is one dictionary lookup rather than a recursive walk. And the existing-SHA set is pre-loaded once, because a point read per SHA meant 4,000 round-trips for a 4,000-commit repository.

Pipeline 3 — A state-changing write

Both halves or 400

Every POST/PUT/DELETE under /api needs the antiforgery pair: the HttpOnly cookie from GET /api/antiforgery/token, and the same token echoed as X-CSRF-TOKEN. Missing either gives 400.

The client cannot read the cookie, which is the point: an attacker's page can cause the cookie to be sent but cannot read the token response to match it.

Two named HTTP clients exist for one reason. "Api" carries AntiforgeryHandler; "ApiRaw" is the same client without it, used by the handler to fetch the token. Routing that fetch back through the handler would re-enter its own gate and deadlock.

The middleware runs after authorization on purpose, so an unauthenticated POST answers 401 rather than 400 — the more useful diagnosis, and what the API tier asserts.

Pipeline 4 — A chart reads

Domain entities and storage

Four tables, keyed for the queries that exist

Table Storage has no joins and no secondary indexes, so the partition key is the query plan. Repositories partition by UserId, so a user's whole list is one scan. Commit snapshots partition by RepositoryId with the SHA as row key, so a repository's whole history is one scan and re-writing a commit is idempotent.

LinesByFileType is persisted as a JSON string because there is no dictionary column type.

Strongly-typed ids (RepositoryId, UserId) are readonly record structs implementing IParsable<T>, which is what lets them bind straight out of a route template — and what makes passing a user id where a repository id belongs a compile error rather than a data leak.

The one number people get wrong

TotalLines is a snapshot of the whole repository at that commit, not a delta. A repository's current size is therefore the value on its newest commit — never a sum across commits, and never windowed. RepositoryTotals (Shared) is the single definition; call it rather than re-deriving. Two pages each grew their own version and printed different numbers under the same label.

State transitions — a repository's life

How it works, in plain English

Ten cards, each pairing a component with the reason it is shaped the way it is. Every one names a specific failure it prevents — that is the house style for comments here, and this document follows it.

1 Counting lines is memoised on git object ids

GitHubService caches per-tree and per-blob counts for the lifetime of its scoped instance, which is one analysis run. Git trees are content-addressed, so an unchanged directory between two commits is one dictionary lookup rather than a recursive walk — replaying history used to decompress every blob of every commit, making analysis scale with commits × repository size.

The tree memo is keyed on object id and path (the ignore filter's answers depend on where a directory sits), it is dropped when the counted-extension set changes, and CountLinesInCommitAsync returns a copy — a caller mutating a memoised instance would poison every later commit sharing that tree.

2 Vendored code is detected by content, not by name

FileIgnoreFilter prunes a directory when its immediate children include two or more repository-root markers (LICENSE*, .github, .gitmodules, CODEOWNERS, CODE_OF_CONDUCT.md, .pre-commit-config.yaml…). That is a whole other project copied in, whatever folder name the author gave it.

Name-based rules cannot catch this. The case it was written for was Unity's ml-agents vendored under Training/, where the old reverse-domain rule caught only the com.unity.ml-agents/ subfolder and left ~78% of the repository's counted lines as third-party. It requires the entry-aware ShouldIgnoreDirectory(path, entryNames) overload — the path-only one cannot see children.

3 Comment syntax lives in one table, and CSS is not C

CommentSyntax maps extension → line/block markers, and both SourceLineCounter (which discards comments) and CodeMetricsAnalyzer (which counts them, and must strip them before looking for branch keywords) read it. Two copies would drift, and both sides would go on producing plausible numbers.

Plain .css has no line-comment form — only /* */ — and was once registered with //, which truncated every line from its first // onward, so url(https://…) lost its tail and a line holding nothing else counted as blank. .scss/.less do have //, which is exactly why they cannot share an entry with .css.

4 Code Health is proxies, and says so on the card

Six line-oriented factors weighted to 100: branch density 30, nesting 20, file size 20, comment ratio 10, debt markers 10, line length 10. It is deliberately not Visual Studio's Maintainability Index — that needs Halstead volume and a control-flow graph, meaning a parser per language and a resolved compilation.

Measuring and judging are separate types, so re-weighting cannot change what was counted. Nesting is the 90th-percentile line depth, not the maximum — using the max let a 40-line middleware holding a wrapped CSS string measure 14 levels deep. And markup is judged on its own nesting band: scoring .razor against the code band gave this repository's own markup a 48 against 94 for its C#, which is a fact about the file format, not the code.

5 Never add a per-item storage lookup a loop will call

CommitExistsAsync was removed for exactly this: a point read per SHA, called once per commit, so a 4,000-commit repository paid 4,000 round-trips (and 8,000 Information log lines) to answer what one GetCommitLineCountsByRepositoryIdAsync already returns for the whole repository. The analysis handler now pre-loads that set unconditionally and looks SHAs up in memory.

6 Analysis progress has exactly one completion path

The hub pushes frames; the fallback poll in Repositories.razor exists only for when the hub is unreachable, and it synthesises the same frames rather than handling completion itself. There used to be three paths, and they had drifted.

Frames carry live tallies, and their collection is replaced, never mutated: Publish serialises the object on a fire-and-forget task while the loop keeps reporting, so appending to Extensions in place would throw mid-serialization. LinesCounted is cumulative churn across replayed commits, not a repository size, and the UI labels it that way.

7 The service worker must not answer a server route

The stock Blazor template serves index.html for every navigation. Here that breaks sign-in outright: the GitHub OAuth round-trip is a sequence of top-level navigations, and returning the Blazor shell in place of one strands the user on a page that thinks it is logged out.

service-worker.published.js keeps a serverRoutePrefixes list (/api/, /auth/, /hubs/, /health, /signin-, /signout-) that goes straight to the network. The development worker is a deliberate no-op, because a worker serving yesterday's _framework/*.wasm is indistinguishable from a build that silently did not take.

8 The recap's windows are calendar edges; the dashboard's are trailing

/api/recap/{year} answers “what did this year look like” — fixed 1 January to 31 December boundaries, an answer that stops changing once the year is over, and figures (peak hour, weekday rhythm, language drift, biggest single commit) that appear nowhere else. That is why it is its own slice, while the digest — the portfolio question over a different window — sits beside GetPortfolioInsightsQuery.

Language drift is measured in share, not lines: a file type's share can grow while the type itself shrinks, because everything else shrank faster. A line-count delta cannot show that.

9 A last visit is only trusted between 12 hours and 90 days

Anything more recent falls back to a trailing 7 days: someone who reloaded twenty minutes ago has no news, and a banner announcing “0 commits since you were last here” looks broken on the one path — an engaged user — where it most needs not to. Anything older falls back too; reporting a year under that label is the recap's job.

The digest's read and its “mark seen” write are separate calls for the same reason. Merge them and a page opened and closed without being read consumes the window.

10 Scoped CSS needs a plain element at the component root

A .razor.css rule compiles to .foo[b-xxx], and nothing a Radzen component renders carries that attribute. Root at a plain <div> (see ChartCard, AnalysisStatusCell) and use ::deep for anything Radzen renders. Rules that silently match nothing have shipped here more than once.

When markup moves between components, its scoped CSS must move with it — otherwise it stays compiled against the old scope id.

Accessibility, because it was broken on every route at once

Every page owns an <h1>, a <PageTitle>, and lives inside the layout's <main>. All three were missing everywhere: the header's brand wordmark was an <h5>, so document outlines ran H5 → H3 → H6 with the brand outranking the page, and every route shared the title “PoRepoLineTracker”. The page title is a real <h1 class="page-hero__title"> in the page's own markup — PageHero cannot change the tag of a fragment handed to it, which is why that class is styled globally rather than in PageHero.razor.css.

The skip link moves focus in code, not by fragment navigation: Blazor's router intercepts anchor clicks, so href="#main-content" scrolled the page and left focus in the nav — a skip link that looks like it works and does nothing for the keyboard user it exists for. MainLayout holds an ElementReference to <main> (focusable only because of its tabindex="-1") and calls FocusAsync on click with preventDefault.

Two things that will bite you

A running app locks the build. dotnet build fails with MSB3027; stop it with Get-Process -Name PoRepoLineTracker.API | Stop-Process -Force.

Unit tests alone are not enough before committing. They pass against changes that break the whole integration tier. Composition-root changes in particular (InfrastructureServiceExtensions, AuthServiceExtensions) are invisible to the unit tier and load-bearing for every integration test. Run Unit + Integration at minimum.

Test conventions

xunit + NSubstitute + FluentAssertions everywhere; no other assertion or mocking library. InternalsVisibleTo is set for both test assemblies, so prefer making a helper internal over testing it through reflection.

Dev/test auth is header-driven: X-Fake-User (a GUID verbatim, any other string hashed to a stable GUID) and optionally X-Fake-Roles. There is no dev-login route. POST /api/dev/seed/repository (Development only) writes synthetic commit history so chart assertions have something to assert on — without it every chart test in E2EUI skips itself and the suite reports false health.

All four tiers are green with zero skips. A skip in E2EUI now means the app isn't up, not that a fixture is missing.

Conventions that fail the build

  • TreatWarningsAsErrors=true, Nullable=enable, LangVersion=preview — a warning fails the build.
  • Trimming is ON for the WASM client; every wire type needs a [JsonSerializable] entry in AppJsonSerializerContext.
  • Config keys go in ConfigKeys (Shared) — no magic strings.
  • Comments explain why, not what. The existing ones name the bug they prevent.
