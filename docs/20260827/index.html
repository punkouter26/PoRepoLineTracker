Why the 404 row matters

The SPA fallback matches /api/typo too, so a misspelled route used to answer 200 carrying an HTML document to a JSON caller. ApiNotFoundMiddleware answers 404 instead — as middleware, not a route, because a catch-all endpoint competes with the real routes and won some of them. It covers GET; other verbs still answer 401 first, which is documented on the type as a deliberate limit.

Response envelope schemas

Success is not wrapped. Handlers return the DTO itself, camel-cased by JsonSerializerDefaults.Web; there is no { data, meta } envelope anywhere in this API, and adding one would break every client binding. Failure has two shapes, and the distinction is which layer caught it.

Handled failure — ErrorResponse

// 4xx from a route, a guard, or ApiNotFoundMiddleware.
// Content-Type: application/json
{
  "title":  "No such route",                 // headline, safe to show a user
  "detail": "GET /api/typo is not an API route on this server.",
  "code":   "route_not_found",               // stable snake_case slug to branch on
  "status": 404                              // repeated in the body so a log line self-describes
}

Unhandled failure — RFC 7807 problem details

// 500 from ExceptionHandlingMiddleware.
// Content-Type: application/problem+json
{
  "status": 500,
  "title":  "An error occurred while processing your request.",
  "detail": "An unexpected internal server error has occurred. Please try again later.",
  "type":   "https://tools.ietf.org/html/rfc7807#section-3.1"
  // Development only, never in Production:
  // "traceId", "exception", "stackTrace"
}
Two shapes, one rule

A client that parses errors must read status from the body or the status line and accept either code (handled) or its absence (unhandled). Prose is for humans; code is the only field safe to branch on. Security-relevant failures never carry internal validation detail in detail — an antiforgery rejection says so without saying which half was missing.

One domain rule to carry into every report

TotalLines on a commit is a snapshot of the whole repository, not a delta. A repository’s current size is the value on its newest commit — never a sum across commits. RepositoryTotals in .Shared is the single definition; two pages once grew their own and printed different numbers under the same label.
