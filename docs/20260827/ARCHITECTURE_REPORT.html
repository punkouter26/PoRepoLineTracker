Tier 1 — Executive

Tier 1Thirty seconds:

One ASP.NET Core (net10.0) process does two jobs: it serves a Blazor WebAssembly client as static files, and it hosts a Minimal API that clones the signed-in user's GitHub repositories, replays their commit history counting source lines, and stores a per-commit snapshot in Azure Table Storage. Everything the UI shows — charts, insights, the recap, code health — is a query over those stored snapshots. Sign-in is GitHub OAuth only, because the app's only data source is GitHub and no other principal carries a credential for it.

Records & contracts

Strongly-typed ids

RepositoryId and UserId are readonly record structs implementing IParsable<T>, which is what lets them bind straight out of a route template without a custom binder, and what makes passing a user id where a repository id belongs a compile error rather than a data leak.

[JsonConverter(typeof(RepositoryIdJsonConverter))]
public readonly record struct RepositoryId(Guid Value) : IParsable<RepositoryId>
{
    public static readonly RepositoryId Empty = new(Guid.Empty);
    public static RepositoryId New() => new(Guid.NewGuid());
    public static RepositoryId Parse(string s, IFormatProvider? provider = null) => new(Guid.Parse(s));
    public static bool TryParse(string? s, IFormatProvider? provider, out RepositoryId result) { ... }
}

The domain snapshot

public class CommitLineCount

The one number people get wrong

TotalLines is a snapshot of the entire repository at that commit, not a delta. A repository's current size is therefore the value on its newest commit — never a sum across commits and never windowed. RepositoryTotals (Shared) is the single definition; call it rather than re-deriving. Two pages each grew their own version and printed different numbers under the same label.

Minimal API route shape

var repos = endpoints.MapGroup("/api/repositories")
    .WithTags("Repositories")
    .RequireAuthorization();

repos.MapGet("/{repositoryId}/linehistory/{days}",
    async (RepositoryId repositoryId, int days, HttpContext ctx,
           IMediator mediator, IRepositoryDataService repoDataService) =>
{
    if (!ctx.User.TryGetUserId(out var userId))
        return Results.Unauthorized();

    var (_, error) = await AuthorizeOwnerAsync(
        repoDataService, repositoryId, userId, "read linehistory for");
    if (error != null) return error;               // 404 if absent, 403 if someone else's

    var history = await mediator.Send(new GetLineCountHistoryQuery(repositoryId, days));
    return Results.Ok(history);
})
.WithName("GetRepositoryLineHistory");

LinesByFileType is persisted as a JSON string (LinesByFileTypeJson) because Table Storage has no dictionary column type.

Storage rule with teeth

Never add a per-item storage lookup that a loop will call. CommitExistsAsync was removed for exactly this: a point read per SHA, called once per commit, meant a 4,000-commit repository paid 4,000 round-trips (and 8,000 Information log lines) to answer what one GetCommitLineCountsByRepositoryIdAsync already returns for the whole repository. The analysis handler now pre-loads that set unconditionally and looks SHAs up in memory.

Telemetry

One ActivitySource and one Meter, both named PoRepoLineTracker v1.0.0, declared in Telemetry/AppTelemetry.cs. Counters: RepositoriesAdded, CommitsAnalyzed, LinesAnalyzed, RepositoryClones, GitHubApiCalls, FailedOperations. Histograms: AddRepositoryDuration, AnalysisDuration, CloneDuration, CommitProcessingDuration, GitHubApiLatency. ASP.NET Core and HttpClient instrumentation are registered alongside them, so an analysis run reads as one waterfall from inbound request through git work to each outbound GitHub call.

TelemetrySettings is the single resolver that both AddTelemetry and /diag consume, so the diagnostics page cannot disagree with what is actually registered. It previously checked only the APPLICATIONINSIGHTS_CONNECTION_STRING environment form and reported “Not configured” for a perfectly configured app.

services.AddHybridCache(options => options.DefaultEntryOptions = new HybridCacheEntryOptions
{
    Expiration = TimeSpan.FromMinutes(5),

});

services.AddHttpClient("GitHubClient", (sp, client) =>
{
    client.BaseAddress = new Uri("https://api.github.com/");
    client.DefaultRequestHeaders.Add("Accept", "application/vnd.github.v3+json");
    client.DefaultRequestHeaders.Add("User-Agent", "PoRepoLineTracker");
    // GitHub:PAT, when configured, covers server-side calls with no user token
})
.AddStandardResilienceHandler(options =>                  // rate limiter -> total timeout ->
{                                                          // retry -> circuit breaker -> attempt timeout
    options.Retry.MaxRetryAttempts   = 3;
    options.Retry.UseJitter          = true;
    options.AttemptTimeout.Timeout   = TimeSpan.FromSeconds(15);
    options.TotalRequestTimeout.Timeout = TimeSpan.FromSeconds(60);
    options.CircuitBreaker.SamplingDuration = TimeSpan.FromSeconds(30);
    options.CircuitBreaker.FailureRatio     = 0.5;
    options.CircuitBreaker.BreakDuration    = TimeSpan.FromSeconds(30);
});

HybridCache is in-memory only here (no IDistributedCache registered), which is correct for a single instance and gains an L2 for free if Redis is ever added. Its stampede protection matters more than raw hit rate: GitHub's REST API is rate-limited per token, so N concurrent page loads must produce one upstream call, not N.

Architectural invariants

Six constraints that are not obvious from the file tree and that a refactor can quietly break.

1 — Slices never reference slices

GlobalUsings.cs omits Features.*, so cross-slice coupling requires an explicit using and is visible in review. Only Extensions/, the composition root, has one. Shared behaviour goes to Auth/ or Shared instead — that is why RepositoryOwnership lives where it does. A copied authorization check fails quietly: the copy stops matching and the symptom is a route serving another user's data, not a broken build.

2 — Static files before UseAuthorization

The FallbackPolicy is applied to requests that matched no endpoint, and static files are served by middleware, not endpoints. With those two calls after UseAuthorization, every asset answered 302-to-login and the browser rendered the Blazor “unhandled error” shell instead of the app.

3 — Registration-time config cannot come from ConfigureAppConfiguration

Those delegates run after Program.cs executes its top-level statements, so anything read during AddInfrastructure(builder.Configuration, ...) will not see them. CustomWebApplicationFactory uses builder.UseSetting(...) for exactly this. Values read lazily at request time are fine either way.

4 — Every wire type needs a [JsonSerializable] entry

Trimming is on for the WASM client and the reflection resolver is deliberately unreachable from it. A DTO missing from AppJsonSerializerContext compiles, ships, and fails in the browser at runtime.

5 — The service worker must not answer a server route

The stock Blazor template serves index.html for every navigation. Here that breaks sign-in outright, because the OAuth round-trip is a sequence of top-level navigations. service-worker.published.js keeps a serverRoutePrefixes list (/api/, /auth/, /hubs/, /health, /signin-, /signout-) that goes straight to the network. The development worker is a deliberate no-op.

6 — Analysis progress has exactly one path

The SignalR hub pushes frames; the fallback poll in Repositories.razor exists only for when the hub is unreachable, and it synthesises the same frames rather than handling completion itself. Do not add a second completion path — there used to be three, and they had drifted.

Unrouted /api paths — middleware, not a catch-all route

The Blazor shell is served by a fallback endpoint matching {**path:nonfile}, which happily matches /api/typo too. An API caller that misspelled a route therefore got 200 with an HTML document, which fails later, somewhere else, in whatever way that caller happens to parse it. In Production it was worse: the auth gate answered 401 for the whole /api prefix before routing ran, so a typo was indistinguishable from an expired session.

// Middleware/ApiNotFoundMiddleware.cs
private static bool IsUnroutedApiRequest(HttpContext context)
{
    if (!context.Request.Path.StartsWithSegments("/api", StringComparison.OrdinalIgnoreCase))
        return false;

    var endpoint = context.GetEndpoint();

    // Nothing matched at all, or the only thing that matched was the SPA shell fallback -
    // which is the case that produced 200-with-HTML. Both mean "no API route claimed this".
    return endpoint is null || endpoint.Metadata.GetMetadata<SpaFallbackAttribute>() is not null;
}

// Program.cs - registered after routing, BEFORE UseAuthentication/UseAuthorization
app.UseMiddleware<ApiNotFoundMiddleware>();
...
app.MapFallbackToFile("index.html").AllowAnonymous().WithMetadata(new SpaFallbackAttribute());
Why middleware and not a catch-all route

A MapFallback("/api/{**rest}") endpoint was tried first and reverted. It becomes a routing candidate next to the real routes, and it won for some of them — POST /api/repositories/bulk started matching the catch-all rather than the bulk endpoint, and because such a catch-all must be anonymous, an unauthenticated write sailed through authorization and was refused by the antiforgery gate with a 400 instead of the 401 it should get. Deciding this outside routing removes the competition entirely: nothing here can shadow an endpoint, because it is not an endpoint.

Placement is equally deliberate — after routing so the match is known, and before UseAuthorization, since otherwise the FallbackPolicy answers 401 for an unmatched path first, which is the exact confusion this exists to remove. The SpaFallbackAttribute marker is used rather than a display-name comparison because the display name is a framework-generated string that no test would notice changing.

Documented scope limit

This fixes GET, not every verb. An unknown /api path reached by GET answers 404; the same path reached by POST/PUT/DELETE still answers 401, because those verbs resolve to something other than the SPA fallback before this runs and the authorization challenge wins. That is deliberate scope: GET was the actively broken case, and the alternative — a catch-all endpoint covering every verb — is exactly what was tried and reverted for shadowing real routes. A write to a route that does not exist being refused as unauthorized is a poor error message; a write to a route that does exist being refused for the wrong reason is a bug.
