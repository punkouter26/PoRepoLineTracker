Tier 1 — Executive

Tier 1Thirty seconds:

The user presses Re-analyze. The endpoint verifies they own the repository, queues the work on a background task, and returns 202 Accepted immediately — a full history replay takes minutes and must not hold a request open. The background job clones or pulls the repository, walks its commits counting source lines, writes one snapshot row per commit, and pushes progress frames to that user's SignalR group as it goes. The page shows a live stage rail, a running line count, throughput and an ETA. If the hub is unreachable, a poll fallback synthesises the same frames rather than handling completion itself — there is exactly one completion path.

Tier 2 — Architectural

Tier 2The hop-by-hop trace, then the same path as a sequence with its failure branches.

The trace

  1. User → browser
    Press “Re-analyze”

    On /repositories/{Id:guid} (RepositoryDetail.razor) or in the grid on / (Repositories.razor). Both call the same endpoint; the grid also owns the AnalysisStatusCell that will show progress.

  2. Blazor component → HttpClient
    AntiforgeryHandler attaches the CSRF token

    The injected HttpClient is the named client "Api", which has AntiforgeryHandler in its pipeline. Because this is a POST, the handler first fetches GET /api/antiforgery/token using a second client, "ApiRaw" — the same client without the handler. Routing that fetch back through the handler would re-enter its own gate and deadlock.

  3. Middleware pipeline
    Five gates, in order

    ApiNotFoundMiddleware (the route exists, so pass) → UseAuthentication (cookie PoRepoLineTracker.Auth) → UseAuthorization (RequireAuthorization on the group) → ProductionAuthEnforcementMiddleware (skips /api entirely) → AntiforgeryMiddleware (unsafe method under /api, so both halves must match).

  4. Endpoint — Features/Repositories/RepositoryEndpoints.cs
    Identity, then ownership

    ctx.User.TryGetUserId(out var userId) reads the UserId claim added during the OAuth ticket. Then RepositoryOwnership.AuthorizeAsync loads the repository: absent → 404, someone else's → 403 plus an IDOR warning naming both user ids.

  5. Endpoint → background task
    Queue and return 202

    Task.Run with a fresh IServiceScope from IServiceScopeFactory — the request scope dies with the response, so resolving IMediator from it would give the job disposed dependencies. The endpoint returns Results.Accepted straight away.

  6. MediatR — AnalyzeRepositoryCommitsCommandHandler
    Take the per-repository lock, or skip

    A static ConcurrentDictionary<RepositoryId, SemaphoreSlim> is waited on with TimeSpan.Zero. If another analysis for this repository is already running the command logs and returns rather than racing — two jobs sharing one local clone path would collide on Checkout().

  7. Handler → AnalysisProgressService
    BeginJob records the owner before any step is reported

    Placed here rather than at the two endpoints that queue the command, because this is where the repository — and therefore its UserId — is actually loaded. The service drops any report for a job whose owner it does not know, so it can never broadcast one user's repository names to another.

  8. Handler → GitHubService → GitClient (LibGit2Sharp)
    Stage 1 — Cloning

    Pull if the local clone is valid; on failure, delete and clone fresh. The access token comes from the stored user row, falling back to the server-configured GitHub:PAT for rows with an empty token or legacy user-less rows. GitHub OAuth is the only provider, so a stored token is always a GitHub token.

  9. Handler → storage
    Stage 2 — Fetching, and one pre-load

    GetCommitStatsAsync lists commits since the last analyzed date. Then the handler loads the whole existing SHA set in one call and looks up in memory. The removed alternative — a point read per SHA — made a 4,000-commit repository pay 4,000 round-trips and 8,000 log lines to answer the same question.

  10. Handler loop
    Stage 3 — Processing, reporting every fifth commit

    CountLinesInCommitAsync per commit, memoised on git object ids. A snapshot row is written per commit. Every five commits a frame goes out carrying stage, counts, cumulative lines and up to twelve discovered extensions.

  11. Handler → storage → hub
    Stage 4 — Saving, then ReportComplete

    LastAnalyzedCommitDate is updated so the next run is incremental. The final frame flips IsRunning to false, and the semaphore is released in a finally.

  12. Hub → browser
    AnalysisFeedClient raises the frame; components re-render

    One scoped hub connection is shared by the repository grid and the activity feed — scoped is the whole app's lifetime in a WASM host, which is what makes “shared” true.

The endpoint — guard, queue, 202

repos.MapPost("/{repositoryId}/reanalyze", async (
    RepositoryId repositoryId, HttpContext ctx,
    IServiceScopeFactory scopeFactory, IRepositoryDataService repoDataService) =>
{
    if (!ctx.User.TryGetUserId(out var userId))
        return Results.Unauthorized();

    var (_, error) = await AuthorizeOwnerAsync(repoDataService, repositoryId, userId, "reanalyze");
    if (error != null) return error;

    Log.Information("Background re-analysis queued for repository {RepositoryId} by user {UserId}",
                    repositoryId, userId);

    _ = Task.Run(async () =>
    {
        // A fresh scope: the request scope dies with the response, so resolving IMediator from it
        // would hand the background job disposed dependencies.
        using var scope = scopeFactory.CreateScope();
        var bgMediator = scope.ServiceProvider.GetRequiredService<IMediator>();
        try
        {
            await bgMediator.Send(new AnalyzeRepositoryCommitsCommand(
                repositoryId, ForceReanalysis: false, ClearExistingData: true));
        }
        catch (Exception ex)
        {
            Log.Error(ex, "Background re-analysis failed for repository {RepositoryId}", repositoryId);
        }
    });

    return Results.Accepted(value: new { message =
        "Re-analysis started. All commit data will be re-calculated with your current file extension preferences." });
})
.WithName("ReanalyzeRepository");

ClearExistingData: true is what makes this a re-analysis: stored counts are deleted and LastAnalyzedCommitDate reset, so every commit is replayed under the user's current counted-extension list. Filter and extension changes only affect new analysis — stored counts need exactly this.

The concurrency guard

private static readonly ConcurrentDictionary<RepositoryId, SemaphoreSlim> _repoLocks = new();

public async Task<Unit> Handle(AnalyzeRepositoryCommitsCommand request, CancellationToken ct)
{
    var semaphore = _repoLocks.GetOrAdd(request.RepositoryId, _ => new SemaphoreSlim(1, 1));
    if (!await semaphore.WaitAsync(TimeSpan.Zero, ct))
    {
        _logger.LogWarning("Analysis for repository {RepositoryId} already in progress - skipping "
                         + "concurrent request", request.RepositoryId);
        return Unit.Value;
    }
    try     { return await HandleInternalAsync(request, ct); }
    finally { semaphore.Release(); }
}

Zero timeout, not a queue: a second re-analysis of the same repository is redundant work, and two jobs sharing one local clone path would collide on Checkout().

The progress frame

public sealed class AnalysisProgressDto
{
    public RepositoryId RepositoryId { get; set; }
    public string Owner { get; set; } = string.Empty;
    public string Name  { get; set; } = string.Empty;

    public string StepName { get; set; } = string.Empty;        // Cloning|Fetching|Processing|Saving
    public string StepDescription { get; set; } = string.Empty;
    public int StepIndex { get; set; }
    public int StepTotal { get; set; } = 4;

    public int CommitsProcessed { get; set; }
    public int CommitsTotal { get; set; }

    public DateTime StartedUtc { get; set; } = DateTime.UtcNow;
    public long LinesCounted { get; set; }                       // cumulative CHURN, not repo size
    public List<string> Extensions { get; set; } = [];           // replaced, never mutated

    public DateTime LastUpdatedUtc { get; set; }
    public bool IsRunning { get; set; }
    public bool IsStuck => IsRunning && (DateTime.UtcNow - LastUpdatedUtc) > TimeSpan.FromMinutes(3);
    public string? ErrorMessage { get; set; }

    public int ProgressPercent => Math.Clamp(
        CommitsTotal > 0 ? (int)Math.Round((double)CommitsProcessed / CommitsTotal * 100)
                         : StepTotal > 0 ? (int)Math.Round((double)(StepIndex - 1) / StepTotal * 100)
                                         : 0, 0, 100);
}
The collection is replaced, never mutated

Publish serialises this object on a fire-and-forget task while the analysis loop keeps reporting. Appending to Extensions in place would throw mid-serialization, so the loop hands over a fresh list each time. LinesCounted is cumulative churn across replayed commits, not a repository size, and the UI labels it that way.

Publish — fire and forget, scoped to the owner

private void Publish(AnalysisProgressDto dto)
{
    // A job with no recorded owner is not broadcast at all rather than broadcast to everyone -
    // that is the case where BeginJob was skipped, and guessing would leak one user's repository
    // names to another.
    if (!_jobOwners.TryGetValue(dto.RepositoryId, out var userId)) return;
    _ = SendAsync(AnalysisHub.GroupFor(userId), dto);
}

private async Task SendAsync(string group, AnalysisProgressDto dto)
{
    try { await hubContext.Clients.Group(group).SendAsync(AnalysisHub.ProgressMethod, dto); }
    catch (Exception ex) { logger.LogDebug(ex, "Dropped progress push for {RepositoryId}", dto.RepositoryId); }
}

Awaiting would let a slow client throttle the work it is reporting on, and letting the send throw would abort an analysis because a browser tab closed. A dropped frame costs nothing: the client reconciles from the snapshot on reconnect, and the polling endpoint is still behind it.

The other end-to-end flows, in brief

Sign-in

/login → GET /auth/login → challenge to GitHub (scopes user:email, read:user, repo) → /signin-github → OnCreatingTicket upserts the UserEntity and adds a UserId claim → cookie issued. If storage is unavailable the OAuth flow is not failed: a warning is logged and a temporary UserId claim is added so the session still works. SameSite=Lax, not Strict — a freshly-set Strict cookie is withheld on the post-login landing redirect, producing an infinite “pick an account” loop.

Adding repositories

AddRepository.razor (a dialog, not a route) calls GET /api/github/user-repositories, cached through HybridCache so N concurrent page loads produce one upstream call rather than N. Selected repositories go to POST /api/repositories/bulk — the only write path, because it dedupes where the removed single-add endpoint did not — and each queues an analysis.

Uploading a ZIP

UploadRepository.razor → POST /api/repositories/upload-zip. Kestrel's body-size limit is raised to 600 MB specifically for this. The extracted tree is analyzed by the same pipeline, so a ZIP and a clone produce identical snapshot rows.

The digest banner

GET /api/insights/digest never records the visit; POST /api/insights/digest/seen does, and the banner calls it only once it has actually rendered. Merging them would let a page opened and closed without being read consume the window. The write is read-modify-write because SavePreferencesAsync upserts with TableUpdateMode.Replace — building the object from anything less than the stored row would silently blank the user's counted-extensions list.
